# Finora

Личные финансы в Казахстане: калькулятор депозитов, справочники ставок БВУ
и учёт регулярных платежей.

Приложение работает **без сервера**: все личные данные хранятся в браузере
и никуда не отправляются. Перенос между устройствами — через файл резервной копии.

## Запуск

```bash
npm install
```

```bash
npm run dev
```

| Команда | Что делает |
|---|---|
| `npm run dev` | Дев-сервер на Turbopack |
| `npm run build` | Продакшен-сборка |
| `npm test` | Юнит-тесты финансовой математики |
| `npm run typecheck` | `next typegen && tsc --noEmit` |
| `npm run lint` | ESLint |

> `typecheck` обязательно начинается с `next typegen`: типы `PageProps` / `LayoutProps`
> генерируются Next-ом, и на чистой копии репозитория голый `tsc` упадёт с
> «Cannot find name 'PageProps'».

## Разделы

| Маршрут | Что там |
|---|---|
| `/` | Обязательства месяца, календарь ближайших списаний, разбивка по категориям |
| `/deposits/calculator` | Расчёт вклада: капитализация, пополнения, база начисления, налог, ГЭСВ |
| `/subscriptions` | Подписки с днём платежа |
| `/expenses` | Фиксированные расходы |
| `/deposits` | Таблица вкладов БВУ, сравнение на одинаковых допущениях |
| `/cashback` | Программы кэшбэка и подбор карты под категорию трат |
| `/data` | Реестр констант с источниками, резервная копия, очистка |

## Устройство

```
src/
├── app/           маршруты, ≤ 40 строк на страницу
├── domain/        чистый TypeScript: деньги, даты, вклады, реестр
├── data/          справочники и датированные константы
├── persistence/   local-first хранилище за подменяемым интерфейсом
├── features/      экраны разделов
├── components/    UI-примитивы, графики, компоненты доверия
└── lib/           форматирование, разбор чисел, вспомогательное
```

`src/domain/**` не импортирует ни React, ни Next, ни `src/data`. Константы всегда
приходят аргументом. Благодаря этому расчёты тестируются на выдуманных константах,
а исправление данных не ломает тесты математики.

## Три решения, которые стоит знать

### Деньги — целые тиыны

`0.1 + 0.2 !== 0.3`, и на расписании вклада в 60 периодов плавающая точка
накапливает расхождение. Все суммы — целые минорные единицы, имена полей
заканчиваются на `Minor`. Тест на 1000 случайных сценариев проверяет, что итог
сходится с точностью до тиына.

### Вхождения платежей считаются от якоря

Наивное «прибавить месяц к предыдущему платежу» даёт тихий дрейф:
31 января → 28 февраля → 28 марта, и платёж навсегда залипает на 28-м.
Каждое вхождение вычисляется как `якорь + n месяцев`, поэтому в марте снова 31-е.
(Нативный `setUTCMonth` на 31 января вообще выдаёт 3 марта.)

### Непроверенные данные помечены на уровне типов

Константу нельзя прочитать в отрыве от её достоверности: `resolve()` возвращает
не число, а `Resolved<T>` с полем `confidence`. Результат каждого калькулятора
несёт `assumptions.worstConfidence`, а интерфейс обязан показать баннер.
Забыть про это нельзя — не компилируется.

Значения со статусом `verified` обязаны иметь ссылку на источник — это проверяется
тестом. Отдельный тест падает, когда в реестре нет значения на сегодняшнюю дату:
так январское устаревание МРП и МЗП становится заметным, а не молчаливым.

## Что требует проверки перед реальным использованием

Проверено по первоисточникам: МРП и МЗП 2026 (4 325 ₸ / 85 000 ₸)
и лимиты КФГД (20 / 10 / 5 млн ₸).

Не сверено и помечено в интерфейсе:

- **Ставки в каталоге депозитов и проценты кэшбэка** — ориентировочные.
- **ИПН на вознаграждение по вкладу** — по умолчанию не удерживается.
- **Методика ГЭСВ** — считается через IRR по денежному потоку; с методикой
  регулятора не сверялась, поэтому подписана как «расчёт finora».

## Зависимости

Сверх Next, React и Tailwind добавлены только `zod` (валидация недоверенного
входа) и `vitest` (тесты). Графики написаны на SVG вручную, дат-библиотеки нет:
нужна была не арифметика дат, а бизнес-правило конца месяца, которого ни одна
библиотека не даёт.
